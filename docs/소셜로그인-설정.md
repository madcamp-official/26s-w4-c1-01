# 소셜 로그인 설정 (카카오·네이버·구글)

백엔드에 OAuth 인가코드 플로우가 구현돼 있다. **키만 발급해 `server/.env`에 넣으면 실로그인이 켜지고**,
키가 없으면 로그인 버튼은 데모 모드(로그인 없이 진행)로 동작한다.

## 공통
- Redirect URI 규칙: `{AUTH_REDIRECT_BASE}/api/auth/{provider}/callback`
  - 개발: `http://localhost:5173/api/auth/kakao/callback` 등 (vite가 /api를 백엔드로 프록시)
  - 배포: `https://<배포도메인>/api/auth/kakao/callback` — `.env`의 `AUTH_REDIRECT_BASE`도 같은 도메인으로!
- `AUTH_SECRET`: 긴 랜덤 문자열(세션 토큰 서명). `openssl rand -hex 32` 추천.
- 적용 후 백엔드 재시작.

## 카카오 (developers.kakao.com)
1. 내 애플리케이션 > 애플리케이션 추가
2. 앱 키 > **REST API 키** → `KAKAO_CLIENT_ID`
3. 카카오 로그인 활성화 + Redirect URI 등록(위 규칙)
4. (권장) 보안 > Client Secret 생성 → `KAKAO_CLIENT_SECRET`
5. 동의항목: 닉네임·프로필 사진(선택 동의)

## 네이버 (developers.naver.com)
1. Application > 애플리케이션 등록 — **'네이버 로그인'** 사용 API 선택
   (쇼핑검색용 키와 **별개 앱**이라 env 이름도 `NAVER_LOGIN_*`로 분리돼 있음)
2. Client ID/Secret → `NAVER_LOGIN_CLIENT_ID` / `NAVER_LOGIN_CLIENT_SECRET`
3. 서비스 URL: 배포 도메인(개발은 http://localhost:5173), Callback URL: 위 규칙
4. 제공정보: 닉네임·프로필사진·(선택)이메일

## 구글 (console.cloud.google.com)
1. API 및 서비스 > 사용자 인증 정보 > OAuth 클라이언트 ID(유형: 웹 애플리케이션)
2. 승인된 리디렉션 URI: 위 규칙 → `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`
3. OAuth 동의화면: 테스트 모드면 테스트 사용자에 팀원 계정 추가

## 동작 확인
- `GET /api/auth/providers` → `{"kakao":true,...}` (키 인식 여부)
- 로그인 버튼 → 플랫폼 로그인 → 앱으로 복귀(`#auth=토큰`) → 마이탭에 닉네임/프로필 표시
- 세션: HMAC 서명 토큰(30일), localStorage 보관. `GET /api/auth/me`로 서버 검증 가능.
